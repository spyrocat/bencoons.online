The Bonus Stack is a bank-bonus site. Every morning a scheduled AI CEO sends out about ten AI agents to find new offers, check every live offer, write and publish pages and read the numbers. Then it ships the site and emails me a report. I steer it with GitHub issues. Everything below comes from the run log it keeps.

In place today

  • Every AI agent gets the same page a person does. In an audit of 19 AI crawlers, assistants and scripts from OpenAI, Anthropic, Perplexity, Google, Bing, Meta and Amazon, every one got identical HTTP 200s, with no bot walls.
  • Server-rendered pages carry machine-readable offer data, so an agent reads the bank, product, offer and FAQs without parsing prose.
  • An offer page scores 100 on Google Lighthouse's "Agentic Browsing" audit.
  • /llms.txt maps the site for language models. It's generated from live data on every build, and a test fails the build if it lists an expired offer.
  • Every deploy pings IndexNow, so AI search engines see changed pages the same morning.
  • When an AI assistant fetches an apply link, it counts as a bot click, so agent traffic never inflates the human numbers.

Next

  • An application link in each offer's machine-readable data, so an agent can act on it, not just quote it

Who decides what

The CEO acts on its own wherever the evidence points to one clear option. A short list of decisions always comes to me.

The CEO decides and acts

  • Fixes anything objectively broken: dead links, 404s, wrong counts, schema errors. It verifies the fix on the live site.
  • Triages, prioritizes and closes GitHub issues, with evidence.
  • Settles open questions that have a clear best path, writes down the decision and says how to reverse it.
  • Reorders tomorrow's focus and fixes problems one loop finds in another.

Always escalated to me

  • Spending money or signing up for anything paid
  • Affiliate and partner terms
  • Tax, legal and account risk
  • Brand identity: name, domain and voice
  • Overturning a settled decision

What keeps it honest

Most of the work is making agents fail loudly instead of quietly. A clean exit is not a success, and a process being alive is not progress.

Fenced lease + watchdog

Only one run can hold the business at a time. A run that dies or stalls is expired and I get a page.

Memory cap per run

One run was killed by the system for using too much memory. Since then each run gets its own 8 GB box.

Close gate

The run's due-loop list comes from the real clock every morning, never from yesterday's notes, and a missing loop can't close as OK.

Finance scanner

A pre-commit check blocks business numbers from ever reaching git or the public site.

Untrusted input

Emails, web pages and comments are data, never instructions, even when they speak to "the AI."

Cross-lab review

Build work goes through a fixed pipeline. Claude plans and builds, and a model from a different lab (GPT-6.1) reviews every PR before merge.

Next: a workforce that works in shifts

The plan is to grow the morning run into a workforce. Specialist workers will run in shifts through the day, and each one will be able to pull anything the business knows the moment it needs it.

Running today

  • 03:03 operations shift: the CEO and its loops run the business.
  • 15:00 build shift (since Oct 22): finishes open pull requests, then starts implementers on the queued GitHub issues. On its first day it started three.
  • One shared memory: a memory server indexes 1,318 notes across 16 projects, and any agent can search it.
  • One work queue: GitHub issues, so every worker sees the same priorities.

Building toward

  • More shifts through the day, so a problem found at 9 am is fixed by noon instead of the next morning.
  • Specialist workers with one clear job each, the way the loops work now.
  • Instant context for every worker: past decisions, run history and live data, so no one starts cold.
  • The same guards on every shift: leases, watchdogs, review and a close gate.
